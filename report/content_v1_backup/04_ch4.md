# 第四章 产业链与价值分配

## 4.1 产业链总体结构

AI 编程工具的产业链可分为上游（基础模型、算力、云服务）、中游（工具与平台）、下游（用户）三层，以及贯穿各层的配套服务（代码托管、后端即服务、部署、可观测性）。与传统软件产业链不同的是，本行业的上游并不只是供应商——三大模型厂商同时在中游自营产品，且中游头部公司正在向上游延伸（自研模型）或被更上游的平台收购。图 4-1 展示了 2026 年 10 月的结构与主要依赖关系。

## 4.2 上游：基础模型、算力与云服务

**基础模型**是本行业最关键的投入。供应关系的三个特征值得记录。第一，**供应商同时是竞争者**：Anthropic、OpenAI、Google 既向 Cursor、Copilot、Lovable 等供模型，又自营 Claude Code、Codex、Gemini Code Assist/Antigravity。第二，**模型接入权已成为竞争杠杆**：2025 年 6 月 Anthropic 以"优先为可持续的合作伙伴保留容量"为由大幅削减 Windsurf 的直接接入，背景是 OpenAI 正拟收购 Windsurf[44]；2026 年 8 月 OpenAI 宣布因 Cursor 被 SpaceX 收购、对其遵守使用条款"缺乏足够信心"，自 11 月 12 日起停止通过 Cursor 提供模型（Cursor 称 OpenAI 模型服务约 5% 的客户，Anthropic 表态将继续增加对 Cursor 的算力支持）[45]。IDC 对此的解读是：竞争单元正从"最佳模型"转向"模型 + harness 组合"[46]。第三，**工具厂商正在用开源基座自研模型以降低依赖**：Cursor 的 Composer 2（2026 年 3 月）被证实基于 Moonshot Kimi K2.5 继续预训练[47]，Menlo 则称其更早的内部模型以 Qwen 为基座[5]；Cognition 有 SWE 系列模型；Base44 推出 Base 1 后，Wix 指引其 2026 年下半年毛利约 60%（年初接近零）[38]。

**算力与云**。Anthropic 的推理运行在 Google 与 Amazon 的服务器上，2025 年推理成本超预算 23%，导致其 2025 年毛利率预测从约 50% 下调至 40%[53]；SpaceX 完成对 Cursor 的收购后，Cursor 据报可使用 SpaceX 的算力集群训练自研模型，此前曾因算力短缺限制训练[184]。微软与 OpenAI 2025 年 10 月的重组协议保留了 Azure 的 API 独占权至 AGI 认定，OpenAI 承诺额外采购 2,500 亿美元 Azure 服务[59]。云厂商同时是分发渠道：Claude Code 可通过 Amazon Bedrock、Google Cloud、Microsoft Foundry 计费到企业云账户[68]。

## 4.3 中游：工具、开发环境与智能体平台

中游按第一章的五类架构划分（表 1-1）。2026 年的格局是：IDE 内嵌助手由 GitHub Copilot 和中国的 Qoder CN、CodeBuddy、文心快码主导；AI 原生 IDE 以 Cursor 为首，Windsurf 已更名为 Devin Desktop 并入 Cognition，另有 Trae、Kiro、Qoder、Google Antigravity；终端/CLI 智能体由模型厂商自营产品（Claude Code、Codex CLI）与开源产品（Aider、OpenCode——后者接入 75 家以上模型提供商）构成；云端异步智能体包括 Codex cloud、Copilot cloud agent、Devin、Jules；一体化平台则有 Lovable、Bolt.new、v0、Replit、Base44、Emergent 以及中国的百度秒哒[84]–[94]。

中游的两个结构性变化是**自营化**与**平台化**。自营化指三家模型厂商的编程产品在 2026 年成为使用率最高的工具（Claude Code 65.5%、Copilot 58.7%、Codex 29.5%）[16]；平台化指独立工具公司被更大平台持有（Cursor → SpaceX，Base44 → Wix，Windsurf → Cognition/Google），以及工具厂商把自己做成分发平台（Cursor 的 Projects、团队市场；Codex 的 Plugins；Claude Code 的插件与技能）。

## 4.4 下游：客户结构

下游客户可分为企业、创业团队与个人/独立开发者三类，收入贡献高度向企业倾斜。Cursor 约 75% 的年化收入来自企业[30]，自报 5 万家以上企业客户、近三分之二的财富 500 强[184]；Claude Code 2026 年 2 月企业使用占收入过半[34]；GitHub Copilot 2026 财年第三季度近 14 万组织使用（媒体转述财报电话会）[182]。一体化平台的客户结构不同：Lovable 的构建者 80% 自称非技术角色，近八成打算把所做的东西变现，超过三分之一已有收入[36][37]；Codex 约 20% 的用户不是软件开发者[35]；Base44 据 Sacra 估计约 1,000 万用户，无销售团队、纯自助式[38]。这意味着**个人与小团队在用户数上是主体，在收入上是少数**——这一错位直接影响厂商的产品优先级（第七章）。

## 4.5 关键接口、模型供应、开发生态与平台依赖

产业链的依赖关系集中在四个接口。**模型 API**：第 4.2 节已述其脆弱性。**MCP 协议**：已被 Claude、ChatGPT、VS Code、Cursor 等客户端支持，2025 年 12 月由 Agentic AI Foundation 中立托管[95][96]，是工具层最成熟的开放接口。**代码托管**：GitHub 是几乎所有云端智能体的交付目标（分支 + PR），也是一体化平台的导出目标；Lovable 支持 GitHub 双向同步但不能导入已有仓库、一项目一仓一分支[83]，这既是用户的"逃生通道"，也是平台黏性的边界。**后端即服务**：Supabase 称 60% 以上的新数据库由 AI 工具创建，Claude Code 与 Codex 自 2026 年 1 月起显著拉动其增长，2026 年 6 月以 100 亿美元投前估值融资 5 亿美元[57]——AI 编程工具正在成为基础设施的分发渠道，同时也把安全配置（如 RLS）的责任转移到了不熟悉它们的用户身上（第五章案例）。

一个新出现的依赖是**订阅账号与第三方 harness 的关系**：Anthropic 于 2026 年 4 月封禁第三方智能体框架使用订阅登录（称其"实际上以订阅价补贴 API 等价负载"），6 月起改为按档位封顶的信用池、按 API 价计费[56]。这表明模型厂商开始区分"自家 harness 的订阅用户"与"第三方 harness 的 API 用户"，并以此保护自营产品。

## 4.6 行业成本结构与价值创造环节

### 4.6.1 成本结构

工具厂商的主要成本是**推理成本**（支付给模型厂商或自有算力）、研发、分发（含免费层补贴）与运营。公开证据表明 2025 年应用层普遍处于负毛利或低毛利：Newcomer 报道 Cursor 2025 年中为"负毛利"、逐周波动，企业定价（席位 + 用量）毛利显著更好[55]；SaaStr 转述某投资机构分析，Cursor 2025 年中年付 Anthropic 约 6.5 亿美元、收入约 5 亿美元，相当于约 130% 的收入付给模型供应商，Anthropic 推出优先服务层后其月账单从 620 万美元翻倍至 1,260 万美元[52]；Sacra 估计 Replit 2025 年毛利在 36% 与 −14% 之间波动，驱动因素是模型接入成本，而托管业务毛利超过 80%[38]；GitHub 2026 年 4 月承认"某些请求的成本已超过计划价格"，暂停个人版新注册并全面转向用量计费[49]。模型厂商自身也不轻松：Anthropic 2024 年毛利率约 −94%，2025 年预期 40%[53]；SemiAnalysis 2026 年 10 月估计其推理业务毛利可达 70%–88%，但消费者订阅约占收入 10% 却消耗 40% 以上的推理算力，毛利约 50%[54]（均为估计值）。

### 4.6.2 价值创造环节

价值创造集中在三个环节。第一，**模型能力本身**——它决定了任务可被委托的上限（第三章 3.4）。第二，**harness 工程**——执行环境、上下文管理、工具调用、验证闭环与计费系统；这是 Cursor 在没有自有前沿模型的情况下达到 40 亿美元年化收入的来源，也是 IDC 所说"模型 + harness 组合难以在别处复制"的含义[46]。第三，**分发与托管**——GitHub 的仓库入口、云厂商的企业账单通道、一体化平台的部署与数据库托管（Replit 托管毛利 80%+）[38]。对应地，价值捕获呈现"两头强、中间弱"：模型层通过 API 价格与供给控制获取大部分价值，分发/托管层毛利稳定，而纯应用层只有在转向企业席位、自研模型或被平台整合后才能改善毛利。

## 4.7 产业链中的关键资源、控制点和进入壁垒

表 4-1 汇总各环节的关键资源与控制点。对小型工具创业者而言，进入壁垒呈两极：一方面，开源智能体（Aider、OpenCode）、开放权重模型、MCP 与 AGENTS.md 标准使构建一个可用的编程智能体的技术门槛很低——Base44 以 6 人自举团队做到被收购[58]；另一方面，在负毛利期生存需要巨额资本（Cursor 累计融资超 30 亿美元，Lovable 超 9.5 亿美元）[28][36]，模型接入权受制于巨头，GitHub 冻结注册 58 天说明容量本身是约束[49]。因此**可行的进入路径不在通用 IDE/智能体，而在依附于开放接口的垂直工作流**——这是第八章讨论机会空白时的前提。
