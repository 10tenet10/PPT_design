# industry-research-deck

把一个行业调研从取证到成片做成 16:9 幻灯片。六步，每步有验收点；脚本与模板在 PPT_design 仓库（`report/`、`decks/`、`tools/`），本文给出不看脚本也能复现的要点。

## 0. 开工前
- 先回一句话说明将做什么，再建任务清单（取证 / 图表 / 成片 / 样张 / 自查）。
- 确认三件事：行业边界、读者、输出（默认 Slides 工件；用户要 DOCX/PDF 才走报告流水线）。
- 用户给了帖子/参考站点时：用内置浏览器逐站浏览（容器网络出不去），截屏记录每站可借的版式元素，再动手。
- 环境准备：新容器先装中文字体（Noto CJK）与 matplotlib；原文站点被网络策略拒绝时，告诉用户要放行哪些域名，同时按 §1 的降级规则继续。

## 1. 立题与证据规则
- 章节骨架（默认 8 章）：定义与边界 / 发展与规模 / PEST 宏观 / 产业链与价值分配 / 用户与细分（含案例）/ 技术与产品 / 竞争格局（五力）/ 风险与预测。
- 证据五类全程标注：**实际值 / 估计 / 预测 / 厂商自述 / 推断**。不同口径的市场规模不能相加；不编排名；不做 STP/4P 与创业建议。
- 每条结论配证据强度：强（多类独立证据一致）/ 中（样本有限或依赖估计）/ 弱（主要基于推断）。
- **标签锁定**：页面与讲稿只用上面五类证据和三级强度，不另造“综合 / 研究 / 来源 / 调研”等标签；调查、论文的数字归“实际值”并写样本量 n。
- **原文打不开时的降级**：只拿到检索摘要、没打开原文的数字不给“强”；两条以上独立检索线查到且一致最高为“中”，单一来源或机构间分歧为“弱”；方法页写明这一限制。
- 每章开头写 `KEYPOINTS … ENDKEY`：三行“事实 | 机制 | 判断”，后面分隔页和讲稿直接复用。

## 2. 取证
- 连接器 → WebSearch → WebFetch 原文；每个数字记：来源编号 [n]、口径、年份、样本量 n。
- 机构预测 vs 厂商收入自下而上互相校验，差两个数量级就写明“口径不同”。
- **校验兜底**：自下而上做不成也要给一个推断区间（写出算法，如“出货 × 均价 + 订阅”），标“推断”；禁止用“口径未对齐，无法给出”当一页的结论。
- **取证完成标准**（每章都过一遍再成片）：
  - 一手文件优先：头部公司有财报、招股书、年报时必须找到并使用（收入、销量、毛利、用户数）；监管与司法文件（药监、专利、海关、法院）用原文编号。
  - 每章至少覆盖这几类中的两类：财报/招股书、第三方出货或份额跟踪（IDC、Omdia、Counterpoint 等）、大样本调查（写 n）、同行评审或验证研究、监管文件；厂商产品页只用于价格与规格。
  - 时效：同一指标有实际值就替换掉预测值；引用前查一次是否有更新的同源数据。
  - 有子代理时按章分 3 路并行检索，每路回报“数字 + 口径 + 年份 + 证据类型 + 来源”，主线程只做合并与去重。
- 正文写成 `content/NN_chX.md`，方言标记：`COVER/TITLE:/SUBTITLE:/META:`、`# 第X章`、`KEYPOINTS…ENDKEY`、`DEF:`、`GAP:`（证据缺口）、`SOURCE:`、`PAGEBREAK`、`LANDSCAPE/PORTRAIT`（节方向）、`FIG: {#key} 标题 | 来源`、`TABLE: {#key w=列宽% fs=字号 split|keep|tail} 标题`（`keep` 整表不拆页，`tail` 允许末行跟下页，`^` 纵向合并，`brk()` 给长词插零宽断点）。
- 报告流水线（需要 DOCX/PDF 时）：`node build2.js` → `post.py` → soffice 转 PDF → `toc_gen.py fill` 跑三遍直到目录稳定 → `rowcheck.py docx pdf` 核对每个表格行都出现在 PDF（LibreOffice 会吞 tblHeader+cantSplit 的行）。

## 3. 图表（matplotlib，`report/figs/common.py` 统一风格）
- 一图一结论：图题是一句话结论，不是“XX 情况”；来源与口径写在图下。
- **新行业直接用通用层**：`tools/deckfig.py`（导入 common.py，换成纸色调色板 `C`、字号 ×1.32，提供 `blank()`、`save()` 和 `wrap_cjk(s, n)`——中文换行、标点避头尾）；作图脚本写成 `from deckfig import …`，范例见 `tools/examples/smart_ring_make_figs.py`。出图默认写到当前目录 `figs_deck/`（环境变量 `FIG_OUT` 可改）。
- 颜色只用调色板 `C`，暖色只给风险/限制；截断的纵轴在图题或轴标签写明“从 X 起”。
- 审计：`python3 tools/figaudit_slides.py <make_figs.py> <out.json>`，按 1664×580 contain 版面换算，报文本重叠、溢出框体、幻灯片像素最小字号（<18px 计入 `n_small`）；先列清单再改，改完再跑一遍。拼一张 contact sheet 人眼复核。
- 旧脚本说明：`tools/figs_deck.py`、`tools/figaudit.py`、`tools/figaudit_deck.py`、`tools/figs_variants.py` 写死了上一份报告的路径，只用于重出 AI 编程工具报告的图，不要拿来做新行业。

## 4. 成片（Slides 工件）
- 先 `list` Design System，有默认就用；没有则用下面的编辑式系统。创建工件后 deck.json + 封面先发，之后每次三页。
- **规格与载体无关**：下面的色板、字体、字号、页面结构是硬规格。环境没有 Slides 工件时，用 PPTX 或 HTML 实现同一规格；环境自带的演示文稿指导与本节冲突时（字体、字号、配色、页型），以本节为准，冲突写进交付说明。
- **信息密度底线**：
  - 每个内容页至少一个带来源编号 [n] 的数字；
  - 标题必须是关于行业的结论（“Oura 全球份额 74%，美国升至 85%”），不能是方法论句子（“证据要分开读”“风险要按条件分析”）；
  - 表格里有数字的行少于 4 行，就改成关键数字页或图页；
  - 方法与限制集中放在方法页，不分散成内容页。
- 页型与规则：
  - 一页一句话结论 + 一张图；图注、数据细节进 `<aside>` 讲稿（≤4000 字）。表格超过 6 行拆页。
  - 色：纸 #F6F3EC、墨 #1A1D22、灰 #5A5F66、细线 #D6D2C8、强调 #244B74、暖 #B9462B（只给弱/限制/风险）、深 #15212E。
  - 字（写稿用规格字号，成片后由 `fit_text.js` 抬到基准并按空间放大，见 §6）：标题 Noto Serif SC 600 46px ≤2 行（width 1560）；正文 Noto Sans SC 20–23px；标签 IBM Plex Mono 20px letter-spacing 2px。成片字号表（1920 画布）：
    | 元素 | 基准 | 上限 |
    |---|---|---|
    | 正文、说明、列表行、关键数字行（稿 20–22） | 26 | 30 |
    | 分隔页三栏（稿 23–24） | 28 | 32 |
    | 发现页结论（稿 27） | 34 | 38 |
    | 等宽标签、页脚、以“来源”开头的说明行 | 22 | 22 |
    | 标题 h2（稿 40 / 44 / 46 / 48） | 44 / 48 / 50 / 52 | 不放大；≤2 行、末行不留孤字 |
    | h1、≥40px 的大数、底图上的定位标签 | 不动 | — |
  - 任何字号不超过 400px（Slides 格式上限，超出会被降级成默认字号）；span 不能带字号，大数与单位分成两个 `<p>` 放进一行 flex。
  - 图页结构：顶栏（`02 — 章名` 左、`图 2-4` 右）→ `<hr width 1664 #D6D2C8>` → h2 → `<img width 1664 height 560–600 object-fit:contain>` → 页脚两条 `position:absolute;bottom:64px`（来源左 width 1300；`证据强度 中 · 15 / 45` 右）；section `padding:96px 128px 160px`。
  - 分隔页：`padding:96px 128px; justify-content:space-between`，260px 衬线数字（#244B74）+ 64px 章名，底部 事实/机制/判断 三栏（mono 标签 19px + 正文 23px）。
  - 关键数字页：4×2 格，数字 56–64px 衬线（单格宽约 380px，长数字用 56px），标签用五类证据之一，页脚注明“口径不同，不可相加”。
  - 发现页：编号 + 一句结论 + 一行证据 + 强度标签；超过 5 条拆两页。
- 格式硬约束：内联样式闭合子集（px、hex；无渐变/阴影/z-index/em）；图片只用上传资产 `/_blob/<id>`；全出血底图放 section 第一个子元素，**其上的正文整体装进一个 `position:absolute;left:128px;top:96px;width:1664px;height:824px` 的容器**，否则会被底图盖住。
- 发布：`root` = 含 `project/` 的目录，`file_path` 一个文件，`files` 其余；改 deck.json 用 Edit；资产用 `asset:true` + `file_paths` 一次最多 25 个。

## 5. 风格样张（用户嫌“AI 感”时）
- 先做样张册再套全册：4 个方向 × 同 4 种页型（分隔/关键数字/图页/发现页），让用户横向比较。
  - A 暗室：dark.design、Linear/Vercel；#0B0D10 底 + #0F1217 面板 + #7AA2FF 强调，Space Grotesk 标题，JetBrains Mono 大写标签。
  - B 海报：recent.design、loadmo.re；#F2EFE6 底，Noto Serif SC 900 巨型数字，4px 黑线，整页朱红 #FF3B1F 陈述页（全册 ≤3 次）。朱红在米纸上只有约 3.1:1，只给 ≥44px 的字；小字的红（证据「中/弱」、表格标注）用 #C8301A（约 4.7:1）。
  - C 极简：minimal.gallery、瑞士网格；纯白，无线条，Space Grotesk 500，两级灰 #555/#8A8A8A，图表单色。
  - D 暖调：Typewolf 的 Daylight；杏 #F3E3C8 + 橄榄绿 #3F4A2E 左侧整栏色块，奶油 #FBF1DF 列表卡，中文数字序号。
- 背景层（从 UI 设计借的静态底，E1–E5；E6 不采用）——原则写在这里，实现与落位全部见 `background-layers.md`：
  - 页型对应：E1 点阵网格 → 封面与章节分隔页；E2 节点连线 → 架构 / 产业链关系页（替代原关系图）；E3 右上走势线（相对亮度 ≤ 正文 40%）→ 新增的一句话结论页；E4 层叠窗口框 → 所有图页；E5 上下色块 → 关键数字页。
  - 一页只用一种；冲突时 E5 > E3 > E2 > E4 > E1。全册可用 E1–E5，但任意相邻 5 页内不超过 3 种；E4 是图表容器，不计入。
  - E2 ≤ 3 页，E3 ≤ 2 页，E5 ≤ 3 页；超过即回到模板感，宁可留白。
  - 背景对比度始终低于正文；底图里不画任何文字（E2 标签用 HTML 叠放，E3 用 `tools/gen_bg_e3.py` 按原始数据重画走势线、标签用 HTML 叠放）。
  - 底图按方向的纸色生成，并上传到目标 deck 自己（资产不跨工件）。

## 5b. 把选定方向套到全册
- 先 `read` 线上版本存到草稿目录，与本地文件 diff，确认没人改过再动手；在草稿目录里用一个转换脚本按页型批量改，最后一次 publish（deck.json + 全部 slides）。增删页（如插入 E3 结论页）后全册页码重排，所有页一起发。
- 换方向同时改 deck.json 的 `faces`（≤4 个）：补齐用到的字重（B 要 Noto Serif SC 900），等宽字体换成方向指定的（B 用 JetBrains Mono）。改 deck.json 用 Edit。
- B 基础页：section `padding:64px 96px 160px; gap:24px`；顶栏 mono 22px + `border-bottom:4px #111`；h2 衬线 900 44px，width 1728，≤2 行；页脚是一个 `position:absolute;left:96px;bottom:56px;width:1728px` 的 flex 行（`border-top:1px #111`，来源左 width 1300，`证据 中 · 15 / 47` 右）。
- 固定定位元素守边界：left+width ≤ 1792、top+height ≤ 952（全出血底图除外）；所有底图、框体排在正常排版的元素之前，否则会盖住正文。
- 容量：发现页 5 条 + 2 行标题时，h2 降到 40px、行内上下 padding 14px 才放得下。
- 背景层的坐标与参数按 `background-layers.md` 的方向参数表取；首次套用后跑第 6 步自查再交付。

### 补充文档
- `background-layers.md`：背景层 E1–E5 的方向参数表（编辑式 / B 海报）、生成方法、写法、用量与主 deck 落位清单。

## 6. 字号填充与自查（用户允许时才做；做之前问一句）
- **先填充**：`node tools/render/fit_text.js <project 目录> <blobmap>`（`--dry` 只报告）。按 §4 字号表把正文抬到基准，再以 2px 步进整页放大到填满可用高度（填充率目标 75–92%），任一约束触发即停：越界、横向溢出、正文触页脚（页脚 top − 8）、绝对定位容器溢出、标题 >2 行或末行孤字。不低于基准时优先选无孤字的字号；字号到顶仍有空间，就把余量平分到带上边线的列表行 padding（每行 ≤ +24px）。
- 工具幂等：首次运行把规格字号的原稿存到 project 同级的 `fit_source/`（不发布），之后总从原稿重算；**改文字改原稿再重跑**，不要在已放大的文件上改。
- 报告里的“孤字：…”行用改写措辞解决（删冗词、换短说法），不靠缩字号；`LOW-FILL`（<60%）说明内容太少或页型不对，交人决定合并、加图或换页型；`NO-FIT` 说明原稿就放不下，先拆页。
- 本地 Chromium（Playwright）1920×1080 渲染每页：`node tools/render/render_deck.js <project 目录> <blobmap> <输出目录>`；blobmap 把 `/_blob/<id>` 映射到本地 PNG（.json 或每行「id 路径」的 .txt），字体用 Noto CJK 替代。旧版 `render.py` / `render_s.py` 路径写死，只属于样例会话。
- 报告三类问题：正文触底（flowBottom ≥ 页脚 top−8）、元素越界/滚动溢出、标题 >2 行；全出血页触底属设计预期要单独说明。
- 拼 contact sheet 人眼复核孤字、换行；先列清单，改完再跑一次，只修清单上的问题。

## 交付话术
- 先说结果（页数、方向、未能做到的），再给一个下一步选择题（选哪个方向 / 哪些背景手法套全册）；不复述过程。
